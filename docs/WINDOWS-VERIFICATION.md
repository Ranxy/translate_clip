# Windows 验证清单

这份清单是自动化测试覆盖不到的部分 —— 需要人眼判断的桌面行为(置顶层级、托盘、安装、自启、快捷键)。

开发与验证都在本机 **Windows 11 + PowerShell 7** 上进行。已经验证过:构建、`npm run typecheck`(干净)、
**162 个单元测试**、以及 `--self-check`(**28 条**,末行 `[self-check] PASSED`;覆盖资源、asar 布局、
sql.js wasm、剪贴板管线、真实翻译、全部设置页、向导)。Linux 仍是交付目标(AppImage / deb,Linux CI 出包),
但 Linux 桌面的平台差异不在本清单范围内(见 `DESIGN.md` §12 的产品限制)。

每一条都给了**预期结果** —— 不一致就是 bug,请按最后一节提供信息。

---

## 0. 准备

| 方式 | 命令 / 操作 | 用途 |
| --- | --- | --- |
| 开发运行 | `npm install` → `npm run dev` | 快速迭代;此时**开机自启不可用**(UI 会置灰说明) |
| 安装包 | `npm run dist:win` 或 Actions 页下载 | 验证真实安装体验、自启、托盘图标 |

自动化检查(三条都跑一次,预期都已在本机确认):

```
npm run typecheck   # 无输出 = 干净
npm run test        # 162 个单元测试全绿
npm run self-check  # 末行 [self-check] PASSED("ok": true 共 28 条)
```

自检会顺带打印平台能力探测,Windows 上应为 `tray: true`、`globalShortcut: "full"`、
`keyring: true`(走 DPAPI);`launchAtLogin` 在开发运行下不可用是**设计如此**(见 §7)。

安装版也可以跑:
`"<安装目录>\TranslateClip.exe" --self-check`(会临时建一个指向本机回环 stub 的
provider 并自动删除,不使用你的真实配置,也不会启动剪贴板监听)。

注意:**应用正在运行时跑 `--self-check` 会直接报错退出**(退出码 2,提示先退出应用),
而不是静默什么都不做 —— 两个进程同时写同一个 `data.sqlite` 会互相覆盖。

## 1. 首启向导

1. 清空配置目录(`%APPDATA%\translate-clip`)后启动。
2. 观察:浮层出现 + 向导窗口自动弹出。
3. 第 1 步顶部把「界面语言」依次切到 日本語 / Русский / English。
4. 第 1 步把目标语言与回落语言设成**相同**。
5. 第 2 步不填任何东西,点「下一步」。
6. 第 3、4 步直接「完成」。

| # | 预期 |
| --- | --- |
| 2 | 向导 4 步;顶部步骤条可点回已完成的步骤 |
| 3 | 每次切换**整个向导立即**换成该语言(步骤条、正文、按钮一起变),下拉框里的语言名始终以该语言自身书写(日本語 / Русский / 简体中文) |
| 4 | 「下一步」**置灰**,并显示"目标语言与回落语言不能相同" |
| 5 | 允许跳过(这是设计),不报错 |
| 6 | 向导关闭;浮层显示"尚未配置翻译服务 / 去配置" |

再启动一次 → **不再弹向导**,且界面仍是第 3 步选定的语言。设置 → 通用 → 「重新运行初始向导」→ 向导重新弹出。
设置 → 通用 → 「界面语言」选「跟随系统(当前:…）」→ 界面立刻回到系统语言,重启后保持;把语言切到非中文后,
**托盘菜单、通知标题与浮层文案一起切换**(主进程用的是同一份 locale 模块)。

## 2. 剪贴板链路

先配置一个 provider(见 §5),然后依次复制下列内容:

| 复制内容 | 预期 |
| --- | --- |
| 一段英文段落 | ~0.4s 内浮层显示原文 + `AUTO → ZH-CN`,随后出现译文 |
| 一段中文 | 方向变成 `ZH-CN → EN-US`(智能互译) |
| 同一段英文(再复制一次) | 立即出结果并带"缓存"标记,**不产生新请求**(开 `llmDebugEnabled` 可在日志看到只有 1 次请求) |
| 只有 1 个字符 | 状态条显示"已跳过:内容过短" |
| 一个纯数字如 `1234567` | 默认**会翻译**(`skipSingleToken` 默认关);在设置里打开后变成"已跳过:单个词或数字" |
| 超过 5000 字符的长文 | 状态条"已跳过:内容过长"(不截断,避免错译) |
| 一张图片 | 无任何反应(只处理文本) |
| **在资源管理器里复制一个文件** | 状态条显示"已跳过:复制的是文件而非文本",**不翻译**(Windows 复制文件时也会把路径放进文本剪贴板) |
| 上一条之后点「立即翻译剪贴板」 | **会翻译** —— 显式请求不被该规则拦截 |
| 快速连续复制 3 段不同文本 | 只翻译最后一段;前两次请求被中断,**不会**出现过期译文覆盖新译文 |

暂停监听(托盘、浮层头部的「监听中」徽标,或状态条右侧的「暂停」)后复制 → 无反应;
再点一次恢复监听,且恢复后**不会**追翻暂停期间的内容。
用浮层空态的「立即翻译剪贴板」→ 即使内容与上次相同也会翻译。
设置 → 剪贴板 的「自动替换剪贴板」与浮层状态条上的同款图标是**同一个开关**:在任一侧切换,另一侧立即跟随,重启后保持。

## 3. 浮层

| 操作 | 预期 |
| --- | --- |
| 让它与浏览器/记事本/终端重叠 | 浮层始终在最上层 |
| 拖动标题栏 | 可移动;重启应用后位置保持 |
| 「─」折叠 | 收成一行内容自适应的小条(不再有「剪译」标题);译文长时条的高度随之增长,最多 6 行、超出以省略号收尾 |
| 折叠后译文折成多行 | 右侧的暂停/清空/展开三个图标由**横排**变成**竖排**(给文字让出宽度);回到一行时自动恢复横排 |
| 折叠条上的图标 | 暂停、清空、展开三个图标都可点,清空后条回到空态且该图标置灰 |
| 状态条上的自动替换图标 | 点击后图标变强调色;**此后每段译文会自动覆盖剪贴板**(复制的内容被替换成译文),且不会再把这句译文翻一遍;再点关闭 |
| 折叠条 | **不显示**自动替换图标(折叠态只有暂停/清空/展开三个,自动替换是设置项而非随手操作) |
| 动作行的「清空」图标 | 原文与译文一起清空,浮层回到空态;没有内容时置灰 |
| 状态条 | 只显示阶段、provider 与「已跳过:…」的原因;不再显示「已捕获 n 字符」 |
| 点浮层头部的「监听中」徽标 | 变成「已暂停」(播放图标);再点一次恢复,徽标回到「监听中」 |
| 点状态条右侧的「暂停」 | 变成「恢复」并转为强调色。这里显示的是**动作**(状态已在头部),所以不应出现「监听中/已暂停」这类状态词 |
| **折叠后**点条上的暂停图标 | 同样能暂停/恢复(折叠态只有这一个入口,不再依赖托盘) |
| 暂停期间复制文本 | 浮层不更新;恢复后也不会补翻这一段 |
| 「✕」关闭 | 浮层隐藏;应用仍在托盘运行,剪贴板监听继续 |
| 从浮层打开设置窗口 | 设置窗口出现在浮层**之上**(浮层让出置顶),能正常点到所有控件 |
| 关闭或切走设置窗口 | 浮层恢复置顶,重新压在其他应用之上 |
| 设置里调透明度 | 立即生效 |
| 开启鼠标穿透 | 浮层不再响应点击;出现"请从托盘关闭"提示 |
| 在穿透状态下复制新文本 | **仍然会翻译**,浮层照常更新(只是不能点) |
| 从托盘关掉穿透 | 恢复可点击 |
| 分辨率缩放改成 150%,重启应用 | 文字不模糊、位置仍在屏幕内 |
| 折叠状态下退出应用并重启 | 仍是那条短条(不会变成一条很高的空条);展开后恢复 520 高度 |
| 双显示器:把浮层拖到副屏,拔掉副屏后重启 | 浮层回到主屏可见区域内(不会跑到屏幕外) |
| 独占全屏的游戏 | **盖不住** —— 这是 Windows/DWM 的限制,把游戏设为"无边框窗口"即可 |
| 依次切到 中文 / English / 日本語 / Русский | 操作行(`[立即翻译][复制][🗑] … [当前\|历史]`)与状态条在四种语言下**都是单行**,不换行、不裁切、按钮不被压扁;俄语下 `Слежу` 徽标与三个窗口按钮也都完整 |
| 空态下点「─」折叠(四种语言各看一次) | 折叠条**只有一行**:俄语是 `Скопируйте текст`,英语 `Copy to translate`;右侧三个图标按钮横排,不会因为提示语太长而挤成竖排或把条变成两三行 |
| 把浮层拖到最小宽度(300) | 任何语言都不被裁掉;只有俄语允许把 `[Сейчас\|История]` 换到第二行(这是设计好的降级) |

> 上面两条已由 `npm run self-check` 的 `overlay localization` 探针自动测量(4 种语言 × 2 个标签页 × 默认/最小宽度);手工再做一次是因为字体回退(Cyrillic / CJK)只有眼睛能判断。

## 4. 托盘与快捷键

| 操作 | 预期 |
| --- | --- |
| 看托盘图标 | 图标可见且**不模糊**(PNG 32px + @2x,DPI 缩放由 Electron 选代表图) |
| 任务管理器里重启 `explorer.exe` | 托盘图标在几秒内自动回来(Windows 会广播 TaskbarCreated) |
| 左键单击 / 双击 | 单击显隐浮层;双击打开设置 |
| 右键菜单 | 第一项随浮层状态变化:浮层可见时是「隐藏浮层」,隐藏后是「显示浮层」;其余为 立即翻译剪贴板 / 监听剪贴板(勾选)/ 折叠 / 鼠标穿透 / 设置 / 打开日志目录 / 退出 |
| 点浮层的「✕」*之后*打开托盘右键菜单 | 第一项已经是**「显示浮层」**(不是仍旧的「隐藏浮层」);点它浮层回来,该项变回「隐藏浮层」 |
| 「退出」 | 真正退出(托盘图标消失,不再监听) |
| 设置 → 快捷键 录制 `Ctrl+Alt+T` | 显示"已生效" |
| 录制一个已被别的软件占用的组合键 | 显示"注册失败(组合键可能已被占用)" |
| 切到别的程序(焦点不在剪译上)按快捷键 | 仍然生效 |
| 重启应用 | 快捷键保持,且仍显示"已生效" |
| 在录制框点一下再按 Esc | 取消录制,不改变已有值 |

## 7. 开机自启(需要安装版)

1. 设置 → 通用 → 打开「开机自动启动」。
2. 任务管理器 → 启动 标签:应出现 TranslateClip。
3. 注销并重新登录。

| # | 预期 |
| --- | --- |
| 2 | 出现该条目 |
| 3 | 应用自动启动,**不弹向导、不弹设置窗口**,只出现浮层并开始监听 |
| 再次打开设置 | 开关仍是"开"(不会读回关闭状态) |
| 关闭开关 | 启动项被移除(任务管理器里消失) |

开发运行(`npm run dev`)下该开关**置灰**,并提示"开发模式下不会写入系统启动项" —— 这是设计,不是缺陷(只有安装版才写启动项,见 §0 的平台能力预期)。

## 9. 如果某一条不符

请提供三样东西,基本就能定位:

1. 出问题的那一条编号 + 你看到的现象(截图最好)。
2. `npm run self-check` 的完整输出(应为 28 条 `"ok": true`、末行 `[self-check] PASSED`;或安装版 `TranslateClip.exe --self-check`)。
3. 日志:`%APPDATA%\translate-clip\logs\main.log`(设置 → 关于 → 打开日志目录)。

日志里已经包含:平台能力探测、剪贴板每次接受/跳过的原因与字符数、每次翻译的耗时与
provider/model、以及所有错误分类。开 `llmDebugEnabled` 还会记录发给模型的完整提示词。
